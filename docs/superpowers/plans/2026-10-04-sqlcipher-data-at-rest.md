# SQLCipher Data-at-Rest Protection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add opt-in SQLCipher encryption through `ILEARNED_DB_KEY`, plus a safe `ilearned db encrypt` migration for existing plaintext databases, without changing the memory-service or surface contracts.

**Architecture:** Runtime configuration resolves the environment-only key and passes `Option<&str>` through `main` into the shared SQLite opener. SQLCipher is compiled via `rusqlite`'s bundled vendored-OpenSSL feature; no key preserves plaintext mode. A storage encryption module performs explicit plaintext-to-encrypted export and verification before the CLI replaces the source file.

**Tech Stack:** Rust 2021, `rusqlite 0.31`, bundled SQLCipher with vendored OpenSSL, SQLite WAL/FTS5, `clap 4`, `serde_json`, existing `AppError`/CLI test harness, and `tempfile` integration fixtures.

**Spec:** `docs/superpowers/specs/2026-10-04-sqlcipher-data-at-rest-design.md`

## Global Constraints

- `ILEARNED_DB_KEY` is the only supported key source; never accept it as a CLI argument or persist it in TOML.
- An unset key preserves plaintext SQLite mode; a present-but-empty or non-UTF-8 key is invalid input.
- Keyed initialization issues SQLCipher's key pragma before any schema access and enables `PRAGMA cipher_memory_security = ON`.
- Use `rusqlite`'s `bundled-sqlcipher-vendored-openssl` feature; do not require system SQLCipher/OpenSSL headers.
- Plaintext-to-encrypted conversion is explicit, confirmation-gated, and uses `sqlcipher_export`; startup never auto-converts.
- Key material must not appear in logs, errors, JSON output, `config show`, or process arguments.
- Preserve the `application::MemoryService` boundary; adapters contain no SQL, lifecycle transitions, or ranking logic.
- Preserve existing path resolution, WAL, FTS, embedding, lifecycle, and public record behavior.
- A failed migration must leave the original database usable and remove any temporary output.
- Update behavior documentation and run `cargo fmt --check`, `cargo check`, `cargo test`, and `cargo clippy --all-targets --all-features -- -D warnings` before completion.

## Review Focus

- **Empty/non-UTF-8 key:** configuration must reject it rather than silently entering plaintext mode; pin this in `tests/config_file_test.rs` in Task 1.
- **Wrong key or key on plaintext:** keyed open must fail with a database-key error without exposing key material; pin this in `tests/storage_test.rs` in Task 2.
- **Already encrypted/corrupt source:** `db encrypt` must refuse without rewriting the file; pin this in `tests/storage_test.rs` in Task 3.
- **WAL/FTS/embedding preservation:** conversion must include derived tables and clean plaintext sidecars; pin this in `tests/storage_test.rs` in Task 3.
- **Confirmation/output leakage:** refusal must not mutate the database, and successful/error/config output must omit the key; pin this in `tests/cli_test.rs` and `tests/config_file_test.rs` in Task 4.

### Task 3: Implement verified plaintext-to-encrypted storage migration

**Files:**
- Create: `src/storage/encryption.rs`
- Modify: `src/storage/mod.rs` (export the migration entry point)
- Test: `tests/storage_test.rs`

**Interfaces:**
- Produces `pub fn encrypt_database(path: &Path, key: &str) -> Result<(), AppError>` in `src/storage/encryption.rs`.
- The function requires a non-empty key and an existing regular plaintext SQLite file; it does not create a source database.
- The function uses a same-directory temporary destination, SQLCipher `ATTACH DATABASE ... KEY ...` plus `SELECT sqlcipher_export('encrypted')`, keyed verification, and cleanup/rollback before replacing the source.

  - `encrypt_database_refuses_non_plaintext_sources`: call it on an already encrypted database and on a file containing non-SQLite bytes, assert an error and byte-for-byte unchanged source;
  - `encrypt_database_requires_existing_nonempty_key`: call it with an empty key and a missing path, assert an error and that no destination file is created;
  - `encrypt_database_failure_cleans_temporary_output`: exercise a failed source/schema/export validation and assert the original bytes remain unchanged and no generated temporary path remains.

- [ ] **Step 3: Add the storage encryption module.**
  Export `pub mod encryption` from `src/storage/mod.rs`. Implement `encrypt_database` with:
  - a `SQLite format 3\0` header check before opening;
  - source opening without a key and existing ilearned schema validation;
  - WAL checkpoint/truncate and connection closure before replacement;
  - a UUID-named temporary file in the source directory;
  - parameter-safe attached destination/key export via `sqlcipher_export`;
